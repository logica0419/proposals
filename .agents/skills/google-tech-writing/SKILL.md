# Google Technical Writing Norms (Reference)

Source: Google developer documentation style guide (https://developers.google.com/style, CC-BY-4.0). This skill distills the rules most relevant to this repo's use cases (technical books, blogs, event reports, CFP proposals). For full text, follow the linked pages.

## Voice and Tone

- Second person, present tense, active voice as default: address the reader as "you" where the brief allows. (https://developers.google.com/style/tone, https://developers.google.com/style/voice, https://developers.google.com/style/person, https://developers.google.com/style/tense)
- Contractions welcome in a friendly tone; stay consistent within a document. (https://developers.google.com/style/contractions)

## Clarity

- One idea per sentence; short sentences for complex procedures. (https://developers.google.com/style/sentence-structure, https://developers.google.com/style/paragraph-structure)
- Prefer strong verbs over nominalizations; avoid anthropomorphism ("the system thinks" -> "the system returns"). (https://developers.google.com/style/anthropomorphism)
- No excessive claims ("simply", "just", "easily", "obviously"). State what holds and under which conditions. (https://developers.google.com/style/excessive-claims)
- Define jargon on first use or link it; assume a global audience. (https://developers.google.com/style/jargon, https://developers.google.com/style/translation)

## Consistency

- Follow the word list for spelling and hyphenation; check product names verbatim. (https://developers.google.com/style/word-list, https://developers.google.com/style/product-names)
- Headings: sentence case, task-focused, no gerund pile-ups. (https://developers.google.com/style/headings)
- Numbers, dates, units: numerals for 10+, spelled-out below; ISO dates in prose. (https://developers.google.com/style/numbers, https://developers.google.com/style/dates-times, https://developers.google.com/style/units-of-measure)
- Code in text: backticks for literals, placeholders in angle brackets. (https://developers.google.com/style/code-in-text, https://developers.google.com/style/placeholders)

## Lists and Procedures

- Parallel structure in lists; lead with the verb in procedural steps. (https://developers.google.com/style/lists, https://developers.google.com/style/procedures)
- Tables for comparisons, not for narrative. (https://developers.google.com/style/tables)

## When to Break Rules

- Guidelines, not rules: depart when it improves the content, then stay consistent within the document. (https://developers.google.com/style#break-the-rules)
